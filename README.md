### 1. Folder Structure & Build System

Keeping your headers and source files separate is standard practice for scalable C++ projects.

```text
SmartHomeProject/
├── CMakeLists.txt
├── include/
│   ├── Logger.h               (Singleton)
│   ├── Device.h               (Interfaces for devices)
│   ├── DeviceFactory.h        (Factory / Abstract Factory)
│   ├── Sensor.h               (Observer Pattern - Subject)
│   └── HomeFacade.h           (Facade)
├── src/
│   ├── Logger.cpp
│   ├── DeviceFactory.cpp
│   ├── Sensor.cpp
│   ├── HomeFacade.cpp
│   └── main.cpp
└── build/                     (Generated by Ninja)

```
**Comands**
To build this using Ninja, you will run:

1. mkdir build && cd build
2. cmake -G Ninja ..
3. ninja

### 2. Development Roadmap

To implement this systematically without getting overwhelmed by the concurrency, divide your work into these four parts:

#### Part 1: The Core Foundation (Singleton & Concurrency)

* **Goal:** Implement the thread-safe `Logger`.
* **Tasks:** * Write the `.cpp` file for the Logger, ensuring `log()` locks the `std::mutex` before writing to the `std::stringstream` or file.
* In `main.cpp`, spawn 5-10 `std::thread` objects that simultaneously write to the logger using your macros (e.g., `LOG_INFO("Thread X starting");`).
* Verify the output file has no garbled text or race conditions.



#### Part 2: The Device Ecosystem (Factory & Abstract Factory)

* **Goal:** Create the devices the smart home will control.
* **Tasks:**
* Create a base `Device` interface with methods like `turnOn()` and `turnOff()`.
* Implement **Abstract Factory**: Create an `IEcosystemFactory` interface with `createLight()` and `createThermostat()`.
* Create concrete factories: `GoogleNestFactory` and `AppleHomeKitFactory`.
* Implement the **Factory Method** inside these classes to instantiate specific device classes (e.g., `NestThermostat`, `AppleLightbulb`). Ensure their `turnOn()` methods use the concurrent `Logger` to report their status.



#### Part 3: The Event System (Observer & Concurrency)

* **Goal:** Make the house react to the environment asynchronously.
* **Tasks:**
* Implement a `Subject` interface and an `IObserver` interface.
* Create a `TemperatureSensor` (Subject). It will run on its own isolated `std::thread`, periodically generating random temperature changes and sleeping.
* Make your `Thermostat` devices implement `IObserver`. Attach them to the sensor.
* When the sensor thread detects a temperature drop, it calls `notify()`, which iterates through observers, prompting the thermostats to turn on the heating. *(Note: Ensure your observer list is thread-safe using a mutex when adding/removing/notifying).*



#### Part 4: The Command Center (Facade)

* **Goal:** Hide the complexity of factories, thread management, and observer attachments from the user.
* **Tasks:**
* Create a `SmartHomeFacade` class.
* Give it simplified methods like `initializeEcosystem(string brand)` (which hides the Abstract Factory logic) and `triggerEveningRoutine()` (which turns off lights and lowers the thermostat).
* In your `main.cpp`, you should only have to instantiate the Facade, call a few simple methods, and watch the concurrent logs output the chaos happening underneath.
